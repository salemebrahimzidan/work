# نظام إدارة العملاء — Customer Management

نظام خاص بسيط (عربي / RTL) لحفظ العملاء ومعاملاتهم وأرباحها.

React + TypeScript + Vite + Supabase (PostgreSQL). متوافق مع الجوال وسطح المكتب.

## المزايا

- تسجيل دخول آمن عبر Supabase Auth — لا يمكن فتح أي صفحة بدون تسجيل دخول.
- العملاء: الاسم، الجوال، الهوية/الإقامة (اختياري)، الجنسية، المدينة، الحي (اختياري)، ملاحظات، تاريخ الإضافة (تلقائي).
- قائمة العملاء مع البحث بالاسم أو الجوال، والتصفية بالجنسية والمدينة.
- بطاقة العميل: البيانات + كل المعاملات + إجمالي ربح العميل.
- المعاملات: اسم الخدمة ومبلغ الربح وملاحظة اختيارية وتاريخ تلقائي. تكرار نفس الخدمة للعميل نفسه يُنشئ معاملة جديدة ولا يستبدل السابقة.
- **الربح يُقفل بعد الحفظ على مستوى قاعدة البيانات** ولا يمكن تعديله أو حذفه أو تصحيحه.
- لوحة رئيسية وتقارير أرباح مع تصفية بالتاريخ والعميل والجنسية والمدينة.

## التشغيل

### 1) إعداد مشروع Supabase

أنشئ مشروعاً على [supabase.com](https://supabase.com)، ثم:

1. افتح **SQL Editor** ونفّذ بالترتيب: `0001_init.sql` ثم `0002_count_every_transaction.sql` ثم `0003_remove_profit_corrections.sql` ثم `0004_admin_profit_edit_delete.sql` ثم `0005_prevent_duplicate_customers.sql` ثم `0006_optional_nationality_city.sql`.
   إذا كانت الهجرة السابقة مطبّقة، نفّذ الملف الجديد فقط. (أو عبر Supabase CLI: `supabase db push`)
2. من **Authentication → Providers → Email**: فعّل Email/Password، وأوقف **Confirm email**
   إن أردت إنشاء الحسابات يدوياً.
3. من **Authentication → Sign In / Providers**: أوقف التسجيل الذاتي
   (**Allow new users to sign up** = off). النظام خاص ولا يحتاج تسجيلاً عاماً.
4. من **Authentication → Users → Add user**: أنشئ حسابك.
   **أول حساب يُنشأ يصبح مشرفاً (admin) تلقائياً.**

### 2) إعداد المتغيرات

```bash
cp .env.example .env
```

ثم ضع في `.env`:

```
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
```

القيم موجودة في **Project Settings → API**. استخدم مفتاح `anon` العام فقط.
**لا تضع مفتاح `service_role` في المشروع إطلاقاً.**

### 3) التشغيل والبناء

```bash
npm install
npm run dev     # التطوير على http://localhost:5173
npm run build   # بناء الإنتاج إلى مجلد dist
npm run preview # معاينة ناتج البناء
```

> ملاحظة: Vite يدمج قيم `VITE_*` وقت البناء، لذا يجب وجود `.env` الصحيح قبل `npm run build`.

## الصلاحيات

لكل مستخدم صف في جدول `profiles` بأحد الأدوار:

| الدور     | الوصول                                                        |
| --------- | ------------------------------------------------------------- |
| `pending` | لا يرى أي بيانات (الحالة الافتراضية لأي حساب جديد)            |
| `user`    | إضافة وعرض العملاء والمعاملات والأرباح — بدون تعديل أو حذف للمعاملة |
| `admin`   | كل ما سبق + تعديل ربح معاملة محفوظة + حذف معاملة + حذف عميل ليس له معاملات |

لاعتماد مستخدم جديد أو ترقيته، نفّذ في SQL Editor:

```sql
-- اعتماد مستخدم عادي
update public.profiles set role = 'user'  where id = (select id from auth.users where email = 'user@example.com');

-- ترقية إلى مشرف
update public.profiles set role = 'admin' where id = (select id from auth.users where email = 'admin@example.com');
```

## كيف يُقفل الربح؟

القفل مُطبَّق في قاعدة البيانات، وليس في الواجهة فقط. محاولة استدعاء Supabase API يدوياً لتعديل
أو حذف ربح تفشل:

1. **RLS**: جدول `transactions` لديه سياستا `SELECT` و`INSERT` فقط. لا توجد سياسة
   `UPDATE` أو `DELETE`، وبالتالي يرفضهما RLS لكل المستخدمين.
2. **الصلاحيات**: تم سحب `UPDATE` و`DELETE` من دور `authenticated` على `transactions`،
   وتم سحب `INSERT` على `profit_corrections`، فلا يوجد مسار لتعديل ربح محفوظ.
3. **Triggers**: التعديل أو الحذف المباشر مرفوض. الاستثناء الوحيد هو استدعاء المشرف
   لـ `admin_update_transaction_profit` (يغيّر عمود `profit` فقط) أو `admin_delete_transaction`.
   أي محاولة لتغيير اسم الخدمة أو العميل أو الملاحظة أو التاريخ تُرفض داخل قاعدة البيانات.
   إنشاء تصحيح جديد ما زال مرفوضاً.
4. **المفاتيح الأجنبية**: `transactions.customer_id` تستخدم `on delete restrict`،
   فلا يمكن إخفاء ربح بحذف العميل.

التقارير تجمع `transactions.profit` مباشرة: كل معاملة محفوظة تُحسب مرة واحدة.

## بنية قاعدة البيانات

| الكائن                    | النوع  | الوصف                                                     |
| ------------------------- | ------ | --------------------------------------------------------- |
| `profiles`                | جدول   | المستخدمون وأدوارهم                                        |
| `customers`               | جدول   | العملاء                                                    |
| `transactions`            | جدول   | المعاملات والأرباح — إضافة فقط، صف جديد لكل حفظ حتى لو تكرر اسم الخدمة، `numeric(14,2)` |
| `profit_corrections`      | جدول   | سجل تاريخي فقط. لا يُستخدم، ولا يمكن إضافة صفوف جديدة      |
| `transaction_details`     | عرض    | المعاملة + العميل + الربح المحفوظ                          |
| `customer_summary`        | عرض    | صفوف قائمة العملاء + عدد المعاملات + إجمالي الربح (بدون الهوية) |
| `customers_by_nationality`| عرض    | عدد العملاء حسب الجنسية                                    |
| `customers_by_city`       | عرض    | عدد العملاء حسب المدينة                                    |
| `transaction_profit_changes` | جدول | سجل تغيير ربح المشرف — غير قابل للتعديل أو الحذف          |
| `transaction_deletions`   | جدول   | سجل حذف المعاملة — يبقى بعد حذف المعاملة                   |
| `admin_update_transaction_profit` | دالة | المشرف فقط. يغيّر `profit` ويسجّل القديم والجديد     |
| `admin_delete_transaction`| دالة   | المشرف فقط. يحذف المعاملة بعد تسجيلها في السجل             |
| `dashboard_stats()`       | دالة   | أرقام اللوحة الرئيسية                                      |
| `profit_report(...)`      | دالة   | تقرير أرباح مُصفّى بالتاريخ والعميل والجنسية والمدينة        |

كل المبالغ `NUMERIC(14,2)` — لا يُستخدم النوع العشري العائم (float) للأموال.
حسابات «اليوم» و«هذا الشهر» بتوقيت `Asia/Riyadh` (قابل للتغيير في الدالة `app_timezone()`).

## الأمان

- RLS مفعّل على كل الجداول.
- الأدوار `pending` لا تصل إلى أي بيانات، فحتى لو فُتح التسجيل بالخطأ لا يُسرَّب شيء.
- المتصفح يستخدم مفتاح `anon` فقط؛ `service_role` غير مستخدم في المشروع.
- `.env` مستثنى في `.gitignore`، و`.env.example` هو القالب الوحيد المرفوع.
- رقم الهوية/الإقامة لا يظهر في قائمة العملاء (غير موجود في العرض `customer_summary`)،
  ويظهر فقط في بطاقة العميل.
- `index.html` يحتوي `noindex, nofollow`.
